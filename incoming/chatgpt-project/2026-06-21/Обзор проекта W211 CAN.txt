TARS на связи.

Это **не готовый CAN-сервер в современном смысле**. Это маленький экспериментальный **C++/Xcode-проект для Mercedes W211 CAN-B**, который читает CAN-кадры через serial-порт, разбирает известные сообщения W211 и иногда отправляет команды обратно в шину. Репозиторий почти без документации: README содержит только заголовок, релизов нет, язык проекта — C++ 100%.

## Что он делает

Программа запускается так:

```bash
./server <port>
```

Дальше она открывает serial-порт, настраивает его на **115200 baud**, non-blocking режим, создаёт `Parser`, подключает его к `BusB` и бесконечно читает входящие данные. То есть она ожидает, что где-то есть внешний CAN/serial адаптер или Arduino-прошивка, которая уже превращает CAN в текстовые строки.

Входящий протокол выглядит примерно так: кадр начинается с `m`, заканчивается `\r`, потом парсер вытаскивает время, CAN ID, длину и до 8 байтов данных. На выходе программа пишет строки вида:

```text
r <address> <len> <data...>
```

То есть это не SocketCAN, не REST API, не нормальный daemon. Это **мост между текстовым serial-протоколом и логикой CAN-B W211**.

## Какие блоки W211 он понимает

В коде есть модель `BusB`, куда заведены отдельные “юниты”:

- `KOMBI` — приборная панель;
- `SAM_V` — передний SAM;
- `DBE` — потолочный блок;
- `EZS` — замок зажигания / центральная логика;
- `TVL` / `TVR` — передние двери / стеклоподъёмники;
- `KLA` — климат;
- `Feature_Windows` — автоматическая логика окон.

Он умеет читать, например:

- положение передних окон;
- lock/unlock события;
- температуру в салоне;
- наружную температуру;
- часть данных приборки: дату, ключ, одометр.

## Самая интересная функция

Главная полезная функция — **автоматическое управление передними окнами**.

Логика такая:

1. Машина разблокирована.
2. Температура в салоне выше 25 °C.
3. Одно из передних окон не открыто достаточно.
4. Программа начинает посылать команду открытия окна.

А при закрытии машины она проверяет положение передних окон и посылает команду закрытия. Команды идут через CAN-сообщение `CANMSG(80, ...)`, где `80` в десятичной форме — это `0x50`.

То есть автор сделал что-то вроде:

> “Если летом открыл машину, а внутри жарко — приоткрой окна. Если закрыл машину — закрой окна.”

Для KITT-проекта это уже вкусно. Не HAL 9000, но пахнет жизнью.

## Диагностика и симулятор

Есть `Diag`, который при включении может отправлять диагностический keep-alive / session message на глобальный KWP2000 ID `0x001c`.

Есть также `AGW_Simulator`, но он выключен по умолчанию. В коде прямо написано: **“DON'T USE IN REAL CAR”**. Он шлёт имитационные кадры, вероятно для тестов мультимедийного/аудио-блока.

## Что в нём ценного для нашего W211 KITT

Ценность не в самом приложении. Ценность в том, что это **готовая карта части CAN-B W211**:

- CAN ID;
- названия параметров;
- битовые смещения;
- длины полей;
- формулы пересчёта температуры;
- пример активной логики: “прочитал состояние → принял решение → отправил CAN-команду”.

Для KITT это можно использовать как **донор знаний**. То есть не запускать этот проект как есть, а вытащить из него:

```text
CAN IDs
bit offsets
decoding formulas
window control logic
lock/unlock detection
temperature extraction
```

И перенести в нормальный KITT CAN-модуль на Raspberry Pi.

## Что плохого

Моё мнение: код как боевой компонент слабый.

Проблемы:

1. **README пустой** — почти нет объяснения, какое железо нужно и какой serial-протокол ожидается.
2. **Проект старый и завязан на Xcode/macOS**, судя по структуре `can_server.xcodeproj` и serial-примеру в коде.
3. **Нет нормальной защиты от ошибок.** Например, если не передать порт, программа печатает usage, но не завершает работу корректно.
4. **Есть вероятная ошибка в логике закрытия окон:** при проверке правого окна используется присваивание `val = W_RF`, а не добавление флага через `|=`, как в логике открытия. Если оба передних окна открыты, команда для левого может быть перезаписана.
5. **Он умеет писать в CAN.** Это уже не пассивное чтение. На машине такое сначала тестируется на столе, потом в read-only, потом с фильтрами, и только потом с командами.

## Итог

Это **экспериментальный CAN-B контроллер для Mercedes W211**, написанный под конкретный serial-CAN мост. Он читает кадры, распознаёт часть блоков кузовной шины и умеет автоматически управлять передними окнами по событиям lock/unlock и температуре.

Оценка TARS:

```text
Как источник CAN-знаний для W211: 7/10
Как готовый сервер для KITT: 2/10
Как основа для своего декодера: 8/10
Как то, что можно сразу запускать в машине: нет, не надо.
```

Правильный ход: **не использовать его как готовую программу**, а вытащить CAN-ID, битовые поля и логику окон в наш собственный KITT CAN-B decoder.
